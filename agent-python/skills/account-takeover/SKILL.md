# 盗号/账户接管（ATO）调查 SOP

## 适用场景
- 用户申诉：账号被改绑手机/邮箱、密码被改、资料被篡改
- 监控发现：账号在新设备登录后短时间内发生敏感操作（改密、转资产、下单）
- 风控拦截：高危操作二次验证失败多次后仍成功

## 调查步骤
1. **固定主体与时间窗**：提取账号/用户 ID、异常操作时间点、涉及资产或资料字段。
2. **事件面核查**：检索该账号近期登录与风控事件，重点看「新设备/异地登录 → 敏感操作」的时间链。
   - 工具：`ticket_query`（customer_name=账号主体，query_type=登录/盗用类事件，limit=20）
3. **资损与业务面核对**：核查账号关联订单/交易在事件时间窗内是否异常（新地址下单、高价商品、即时转卖特征）。
   - 工具：`sales_query`（query_type=按客户，period=近7天）
4. **情报佐证（可选）**：如工具目录中存在外部情报检索类工具，检索同手法团伙/钓鱼渠道情报；目录中没有则跳过并在 thought 说明。

## 结论标准
- **malicious**：新设备/异地登录与敏感操作时间链闭合，且业务面证实资损或资料被篡改
- **suspicious**：存在异常登录或敏感操作，但资损证据不足（可能为用户亲友/二手设备操作）
- **benign**：全部操作可归因于用户本人多端行为，时间链与常用轨迹一致

## 处置建议模板
- malicious → 冻结账户资产 + 强制下线全端 + 恢复绑定渠道（需人工审批）；关联新设备指纹进黑名单观察
- suspicious → 强制二次验证 + 7 天敏感操作留痕观察
- benign → 回复用户关闭工单，提示开启登录保护
