# 优惠券套现/羊毛党调查 SOP

## 适用场景
- 新客券/拉新奖励被同一设备或支付账户批量领取
- 「领券 → 下单 → 退款 → 券不回收」组合套利
- 优惠后商品价格异常击穿成本，订单集中在特定 SKU

## 调查步骤
1. **固定主体**：提取账号/设备指纹/支付账户/收货地址，确认活动 ID 与时间窗。
2. **事件面核查**：检索领券与核销相关客诉工单，统计同主体关联的账号数量与领券金额。
   - 工具：`ticket_query`（customer_name=主体或手机号，query_type=营销/优惠类事件，limit=20）
3. **业务面核对**：核对活动期间订单与优惠金额曲线，识别「同支付账户多账号下单」「下单后快速退款」组合模式。
   - 工具：`sales_query`（query_type=按客户，period=近7天）
4. **情报佐证（可选）**：如工具目录中存在外部情报检索类工具，检索同活动羊毛党团伙情报；没有则跳过。

## 结论标准
- **malicious**：多账号归因到同一设备/支付账户，且套利链路（领券-下单-退款）证据闭合
- **suspicious**：优惠订单异常集中但存在家庭/合租等合理解释空间
- **benign**：订单行为与正常促销流量特征一致

## 处置建议模板
- malicious → 冻结涉事活动发券（需人工审批）+ 回收异常券与订单拦截；设备指纹/支付账户维度拉黑
- suspicious → 涉事订单延迟履约转人工审核，同设备新领券加验
- benign → 放行，工单归档
