# 爬虫/批量抓取调查 SOP

## 适用场景
- 单 IP/UA 短时请求量远超人类操作上限
- 监控发现价格、库存、商品详情接口被高频轮询
- 站外出现与站内同步的内容/价格镜像

## 调查步骤
1. **固定特征**：提取 IP 段、UA/设备指纹、目标接口、时间窗与请求量级。
2. **事件面核查**：检索相关风控工单与拦截记录，确认是否已有识别与处置动作。
   - 工具：`ticket_query`（customer_name=IP 或线索主体，query_type=爬虫/流量异常类事件，limit=20）
3. **业务面核对**：核对被抓取接口对应的业务数据面（价格/库存近期变动），评估泄露影响面。
   - 工具：`sales_query`（query_type=按客户，period=近7天）
4. **手法画像（可选）**：如工具目录中存在外部情报检索类工具，检索该 UA/IP 段的公开画像；没有则跳过。

## 结论标准
- **malicious**：请求模式非人类（规律间隔/无页面资源加载/高频轮询），且目标为敏感业务数据
- **suspicious**：流量异常但可能是聚合 SDK/合作伙伴回调所致，需业务方确认
- **benign**：为搜索引擎合法爬虫（验证 UA 归属）或压测流量

## 处置建议模板
- malicious → IP/UA 段限流或封禁（需人工审批）+ 敏感接口加签名校验；对已泄露数据面评估影响
- suspicious → 加验证码/限流观察，联系业务方确认流量来源
- benign → 放行，白名单登记
