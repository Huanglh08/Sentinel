# 撞库/账户盗用调查 SOP

## 适用场景
- 用户反馈账号异地登录、资产变动非本人操作
- 监控发现单账号短时多次登录失败后成功
- 外部情报爆出站点库泄露，需排查受影响账号

## 调查步骤
1. **固定线索**：从线索中提取主体（账号/设备/IP/时间窗）。缺失关键主体时，先用工单检索补全上下文。
   - 工具：`ticket_query`（customer_name=账号主体或手机号，query_type=登录/盗用类事件）
2. **事件面核查**：检索该主体近期的登录与风控事件，确认失败次数、失败原因分布、成功登录的时间与来源。
   - 工具：`ticket_query`（status=open 与 closed 各查一次，limit=20）
3. **业务基线核对**：查该主体关联的业务数据是否出现异常变动（订单/交易突增、积分/余额异动）。
   - 工具：`sales_query`（query_type=按客户，period=近7天）
4. **情报佐证**：检索外部情报，确认近期是否有同源泄露/撞库活动、攻击者使用的常见 IP 段或手法。
   - 工具：`youcom_search`（query=「撞库/credential stuffing + 泄露源/站点名」，freshness=oneMonth）

## 结论标准
- **malicious**：成功登录时间与用户常用地不符 + 登录后伴随资产变动 + 情报证实同源撞库活动
- **suspicious**：存在异地/异常时段登录或批量失败，但资产变动无法证实
- **benign**：失败为用户自身多端尝试所致，登录轨迹与用户行为一致

## 处置建议模板
- malicious → 冻结账户 + 强制下线 + 改密（需人工审批）；同 IP/设备关联账号批量排查
- suspicious → 账户加验（二次验证/短信校验），持续观察
- benign → 放行并关闭工单
